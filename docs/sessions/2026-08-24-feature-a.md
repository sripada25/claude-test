## S-16 · Blocker resolution → `L040`, `L041`, `L046`, `L052`, `L053`

**Ledger (approved):**

| ID | Decision |
|----|----------|
| L040 | Email verification required — **before first AI generation**, not before signup |
| L041 | Capture user timezone at signup from the browser |
| L046 | `experience_level` enum: Junior / Mid / Senior / Lead |
| L052 | Password: min 12 characters, no complexity rules, no breach-check in MVP |
| L053 | PRD Phase 0 does **not** gate the build. WhatsApp validation runs in parallel with F1/F2 |

**Why (from ledger):** Verification should not kill signup, but it must gate the moment cost and abuse exist (free generations, 12-day trial). Timezone cannot be backfilled accurately later; reminders otherwise fire at the wrong local hour. Experience as free text makes generation inconsistent. Length beats symbol-soup for passwords. F1 (accounts) and F2 (tracker) are required in every scenario, including a pivot away from call notes; only F5 (post-call log) depends on that research.

## S-18 · A2 — Skills storage → `L045`

**Ledger (approved):** Skills as free-text tags, Postgres `text[]`, lowercase-normalized.

**Why (from ledger):** PRD names `skills` but does not specify storage (`[ASSUMPTION]`). In MVP, skills only feed the Gemini prompt, which does not need a controlled vocabulary. A canonical skills list only pays off for job matching, which is out of MVP.

<a id="s-19--a4--resume-auto-fill-ai-vs-script--l047-l048-l049"></a>

## S-19 · A4 — Resume auto-fill (AI vs script) → `L047`, `L048`, `L049`

**Ledger (approved):**

| ID | Decision |
|----|----------|
| L047 | Profile is **mandatory** before app access. Flow: signup → profile (manual **or** resume upload) → complete → app |
| L048 | Hybrid pipeline: `pdf-parse` (deterministic, free) → Gemini Flash to structure → pre-filled form → **mandatory review** → save |
| L049 | Parse output is **never saved blind** |

**Why (from ledger):** Mandatory profile removes “gate generation on completeness.” Extra signup friction is mitigated by resume upload. Script-only parsing is weak on two-column layouts and tables (~40–60%). Cost fear was inverted: parse is ~1 Gemini call per user ever, vs thousands of generation calls per month. The review step is what prevents garbage, not mandatoriness alone.
